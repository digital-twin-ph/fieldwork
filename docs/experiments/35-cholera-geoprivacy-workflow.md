# Cholera geoprivacy workflow: semantic admission and evaluation

_Created 2026-10-07 · Updated 2026-10-08_

Status: bounded prototype, 2026-10-07. Source case-study coordinates remain private inputs in this exercise. The 1854 data are used to explain transformations, not to assert a contemporary disclosure risk or prove a privacy guarantee.

## Admission decisions

| Candidate | Meaning and boundary | Typed contract | Decision |
| --- | --- | --- | --- |
| Hide data | Suppress a specifically reviewed record when context around its point makes disclosure risky. A risk finding needs a reason and reviewer; proximity alone is not the finding. | Private points + contextual review decisions -> released points, with an internal suppression receipt. Missing locations need an explicit policy. | TODO: wait for an apt, defensible example. Do not equate a map visibility toggle with suppression. |
| Move data | Donut geomasking: move each located point a sampled distance within a configured annulus, using a reproducible demonstration seed. It is neither encryption nor guaranteed anonymity. | CRS84 points -> CRS84 derived points; inner/outer radii in metres; missing coordinates rejected. | Admit as a distinct processing primitive. |
| Mean center | Compute the unweighted arithmetic mean of projected point coordinates. This describes location balance, not a representative person, burden-weighted center, or privacy metric. | CRS84 points -> one CRS84 center with source count and WGS84 UTM computation CRS; reject empty/missing locations or coordinates outside the configured projection guard. | Admit as a reusable processing primitive, once for each point branch. Internal reprojection is recorded; no projected dataset is produced. |
| Compare point sets | Compare two independently computed mean centers and locate both against the same reference pump layer. This evaluates aggregate spatial displacement, not disclosure risk or pairing. | CRS84 original points + CRS84 moved points + two typed mean centers + CRS84 reference points -> comparison summary; matching computation CRS and source counts required, distances in metres. | Admit as a reusable evaluation operation. Map presentation consumes its result without recomputing centers. |
| Group data | H3 cell aggregation: count locations in each cell, then release only cells meeting a minimum occupancy. H3 resolution is an index level, not a metre quantity. | CRS84 points -> cell polygons and location counts in CRS84; integer resolution and occupancy threshold; missing coordinates rejected. | Admit as a distinct processing primitive, not Voronoi catchments. Summing attributes is future work. |
| Encrypt map data | Reversible tile permutation plus authenticated residual encryption in the reference notebooks. An encrypted ZIP of a layer is a different packaging operation. | Requires key lifecycle, attacker model and before/after map semantics. | TODO: choose a faithful bounded cryptographic implementation after reviewing the desired map artifact. |

### Planned map-encryption widget and notes popup

Expose calibration controls as an explicit plan, not magic privacy strength: projected metric CRS, tile width (metres), destination-domain extent, key source and rotation label, authenticated residual mode, display wobble radius, and an evaluation sample/seed. Separate the encryption key from any display-jitter key. Warn when parameter choices or a small destination domain make candidate-tile attacks plausible; these are diagnostics rather than certification.

Model three connected activities rather than one opaque result:

1. **Encrypt map data:** private source points plus calibrated plan and keys -> encrypted coordinates, key-free display map, and restricted recovery artifact. Display coordinates, ciphertext and recovery material are distinct entities. The key-free map must not silently incorporate original coordinates.
2. **Decrypt map data:** encrypted coordinates plus authorized recovery material and key -> recovered private points, with authenticated failure on tampering, wrong key or mismatched parameters. The recovered map and table stay in the private workspace.
3. **Evaluate map encryption:** compare original, encrypted/display and recovered data in private views. Report displacement distribution, tile occupancy/domain, round-trip coordinate error, decode success/failure, artifact sizes and a stated candidate-tile/linkage attack test. Separate confidentiality, recoverability and geographic utility; success on one is not success on all. The before/after and recovery maps/tables must identify their audience and export sensitivity.

All three stages should emit provenance activities, typed quantities and SHACL-constrained receipt structure. Export should require a deliberate choice of which artifacts to include. The future widget's `?` notes popup should link directly to the [geoprivacy notebooks](https://git.cdc.gov/jupyterlite/2026-Map-Encryption-Library) for a deeper explanation of tile permutation, residual encryption, key separation and evaluation. Its catalog status must remain proposed until implemented and validated.

The widget is the reusable definition; each canvas node is a parameterized `prov:Plan`; a run is a `prov:Activity` using private source entities and generating derived entities. Map and table outputs are presentations, not further geomasking. A derived-layer download must not include source coordinates, original record identifiers, source tables, or private run receipts. Whole-project export and run receipt remain private/source-bearing, even when a Results tab shows transformed data. No notebook’s privacy score is a guarantee for this historical sample.

## Worked-example comparison

Two Mean center widgets receive the original and moved branches separately. Each computes the arithmetic mean of projected easting/northing in WGS84 UTM zone 30N, then converts its center back to CRS84. Compare point sets receives both typed centers, their corresponding point sets, and the eight historical pump points. The UTM projection is an internal, inspectable computation parameter; it does not yield a reusable reprojected dataset. The summary reports center-to-center displacement and each center's nearest pump distance in metres. Both side-by-side maps use one extent and scale, show the same pump symbols and mean-center markers, and stay private because the left map exposes original locations. This does not measure individual displacement, reidentification risk, historical pump use, or weighted deaths. Reject empty inputs, missing locations, unequal original/moved counts, and coordinates outside the configured UTM guard. The computation receipts must bind each point source to its Mean center, and the comparison must bind both center entities, both point sources, the pump source, the CRS, center geometries, counts and measured distances; the map receipt records presentation only. SHACL validates the receipt structure, while numerical tests validate projection and map consistency.

Use the existing 250 John Snow death *locations* (whose `DEATHS` values total 489), preserving the source citation. The private before map/table show original coordinates. The move branch uses the notebook’s illustrative 50–125 m annulus. The group branch uses an H3 index and occupancy threshold. Each after branch gets a map and table, plus a derived-layer export that contains only that branch’s output. The interface must identify which tabs and exports are private. Do not present the shifted and binned branches as a sequence unless the canvas connects them that way.

The reference is the local checkout of [Map Encryption Library](https://git.cdc.gov/jupyterlite/2026-Map-Encryption-Library) at `948eeda`. Notebooks `00a-donut-geomasking.ipynb`, `00b-donut-geomasking-evaluation.ipynb`, and `00c-hex-grid-binning.ipynb` inform the methods. The encryption notebooks specify a distinct reversible map transform; this prototype does not claim to implement it.

## Validation contract and limits

Positive tests: radii constrain every moved point, a fixed seed reproduces the example, each source location belongs to exactly one H3 cell, occupancy filtering omits small cells, released exports contain only derived IDs and geometry, and executed RDF conforms to SHACL. Negative tests: invalid units/resolutions, missing coordinates, malformed source attributes, and attempted conflation of hex cells with catchments fail. Browser checks inspect actual before/after tabs and the N3 & evidence view. A private run receipt intentionally retains source lineage, so it is not a publishable privacy artifact. Linkage, reidentification, analyst utility, and a motivated attacker are separate evaluations not established by these checks.
